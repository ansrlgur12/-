# 직좌우 (가제)

**실제 동네 지도 위에서, 교차로마다 가위바위보로 갈 방향을 정하는 3인 온라인 게임.**

세 명이 각자 자기 기기에서 접속해 한 일행을 함께 움직인다. 교차로를 만날 때마다 가위바위보를 하고, 이긴 사람이 맡은 방향으로 간다. 목적지에 도착할 때까지 몇 번의 가위바위보를 했는지, 얼마나 걸렸는지가 기록으로 남는다.

> 목표: 첫 앱 출시 경험 + 포트폴리오. 수익화는 부가 목표.

---

## 1. 게임 규칙

### 플레이어와 방향

| 플레이어 | 담당 방향 |
|---|---|
| A | 좌회전 |
| B | 직진 |
| C | 우회전 |

- 3명은 각자 자기 기기에서 접속한다 (온라인 멀티플레이).
- 세 사람은 지도 위의 **한 일행(마커 하나)**을 함께 움직인다.

### 교차로 가위바위보

1. 일행이 교차로에 도착하면 가위바위보가 시작된다.
2. **그 교차로에 없는 방향을 맡은 플레이어는 이번 판에서 빠진다.**
   - 십자 교차로(좌·직·우): A, B, C
   - 좌·우만 있는 갈림길: A, C
   - 좌·직만 있음: A, B
   - 직·우만 있음: B, C
   - 갈 수 있는 방향이 하나뿐(굽은 길 등): 가위바위보 없이 그 방향으로 진행
   - 막다른 길: 가위바위보 없이 자동 유턴
3. 판정
   - **한 명이 이기면**: 그 사람의 방향으로 이동
   - **두 명이 이기면**: 그 두 명끼리 **한 명이 이길 때까지** 다시 가위바위보 (두 명끼리 비기면 계속 재경기)
   - **첫 판에서 전원 무승부**(모두 같은 것, 또는 셋이 모두 다른 것): **뒤로 돌아간다** (왔던 길로 유턴)
   - 참가자가 두 명인 갈림길에서 첫 판이 비기면: 전원 무승부로 보고 유턴
4. **가위바위보 횟수는 재경기를 포함해 한 판 한 판 모두 센다.**

### 도착 판정

- 목적지는 가장 가까운 도로 지점으로 보정한다.
- 일행이 목적지 반경 안(기본 30m, 조정 가능)에 들어오면 도착으로 처리한다.

### 선택 제한 시간과 자리 비움

- 가위바위보마다 **20초** 안에 선택해야 한다.
- 20초 안에 선택하지 않은 플레이어는 **자동 퇴장**되고, 그 자리는 **AI 플레이어**가 이어받는다.
  - 시간이 지난 그 판의 선택도 AI가 대신한다.
  - AI는 가위·바위·보 중 무작위로 낸다.
- 퇴장된 유저가 방으로 돌아오면 **자기 자리를 AI에게서 다시 넘겨받아** 이어서 플레이한다.
  - 진행 중인 판이 있으면 그 판은 AI가 마무리하고, 다음 판부터 유저가 플레이한다.
- 앱이 꺼지거나 네트워크가 끊긴 경우도 같은 방식으로 처리한다.

## 2. 게임 모드

### 일반 모드

방장이 방을 만들 때 아래 중 하나를 설정한다.

- **제한 시간** (예: 15분, 30분, 1시간)
- **제한 턴 수** (가위바위보 횟수 기준, 예: 50회, 100회)

제한에 도달하면 게임이 멈추고 안내 화면을 보여준다.

```
⏰ 제한 시간이 끝났어요!

총 가위바위보   87회
총 이동 거리    2.4km
목적지까지      650m 남음

[ 기록 남기고 종료 ]   [ 계속 진행하기 ]
```

- **기록 남기고 종료**: 미완주 기록으로 저장하고 게임 종료
- **계속 진행하기**: 제한 없이 이어서 진행. 이후 도착하면 "연장 완주" 기록으로 저장

### 하드코어 모드

- 제한 시간, 제한 턴 수 없음
- **도착했을 때만** 기록을 저장할 수 있다
- 중간에 포기하면 기록이 남지 않는다

### 기록 항목

| 항목 | 설명 |
|---|---|
| 모드 | 일반 / 하드코어 |
| 결과 | 완주 / 연장 완주 / 미완주 |
| 총 가위바위보 횟수 | 재경기 포함 |
| 실제 플레이 시간 | 게임 시작부터 종료까지 실제 경과 시간 |
| 총 이동 거리 | 실제 도로 기준 |
| 남은 거리 | 미완주 시 목적지까지 직선 거리 |
| 이동 경로 | 지도에 다시 그려볼 수 있는 좌표 목록 |
| 출발지 / 목적지 | 장소명과 좌표 |
| 참가자 | 3명과 각자 담당 방향 |

### 미정 항목 (TBD)

- 일반 모드에서 제한 도달 시 "종료 / 계속"을 **누가 정하는지** (방장 결정 / 3인 투표). 초안은 방장 결정.
- 일반 모드에서 제한 전에 직접 포기했을 때의 처리
- 3명이 다 모이지 않았을 때 AI로 빈자리를 채우고 시작할 수 있는지

## 3. 방

- 방장이 방을 만들고 **출발지(동네)**, **목적지**, **모드와 제한**을 설정한다.
- 출발지와 목적지는 장소 검색으로 고른다 (예: "망원동", "OO역 스타벅스").
- 목적지가 출발지에서 너무 멀면 경고한다 (무작위 이동이라 거리가 멀면 도착이 매우 어렵다).
- 친구는 초대 코드로 입장한다.
- 입장 순서 또는 방장 지정으로 A / B / C 자리를 배정한다.
- 3명이 모이면 방장이 시작한다.

## 4. 지도와 길 판정

### 데이터 소스

- **도로 그래프**: OpenStreetMap (ODbL 라이선스, 앱 내 출처 표기 필수)
  - 개발 초기: Overpass API로 출발지 주변 반경의 도로(이후 건물 윤곽·층수 포함)를 받아온다.
  - 출시 전: Geofabrik의 대한민국 OSM 추출본을 받아 서버에서 전처리해 자체 보관한다 (외부 API 의존과 요청 제한 회피).
- **보행 가능 도로만 사용**: 고속도로, 자동차 전용도로 등은 제외한다.
- **장소 검색**: 카카오 로컬 API (한국어 장소명 검색)
- **지도 표시**: 지도 SDK나 타일을 쓰지 않고, OSM 도로·건물 데이터로 3D 동네를 직접 그린다 (아래 "3D 동네 표현").

### 3D 동네 표현

- **렌더링**: Three.js + React Three Fiber (네이티브, expo-gl)
- **도로**: OSM 도로를 폭이 있는 띠(메시)로 바닥에 그린다. 큰길과 골목은 폭과 색으로 구분한다.
- **건물**: OSM 건물 윤곽을 층수(`building:levels`)만큼 올린 로우폴리 블록으로 그린다. 층수 정보가 없으면 기본 높이를 쓴다.
- **캐릭터**: 3명(A/B/C)이 로우폴리 3D 캐릭터로 실제 도로를 따라 걷는다 (glTF, 걷기 애니메이션).
- **카메라**: 일행을 따라가는 비스듬한 게임 시점. 줌으로 주변을 넓게 볼 수 있다.
- **장소 표시**: 지도 앱 수준의 상호명은 표시하지 않는다. 출발지·목적지만 표지로 보여준다.
- **성능**: 출발지 주변 반경만 불러오고, 도로·건물은 각각 하나의 메시로 합쳐 그린다.

### 그래프 구성

- 도로를 **노드(지점)와 엣지(길)**로 변환한다.
- 연결된 길이 3개 이상인 노드 = **교차로**
- 연결된 길이 2개인 노드 = 그냥 지나가는 지점 (가위바위보 없음)
- 연결된 길이 1개인 노드 = **막다른 길** (자동 유턴)

### 좌·직·우 판정

- 들어온 길의 진행 방향과 나갈 수 있는 각 길의 방향(bearing) 차이로 분류한다.
  - 차이 −30° ~ +30°: 직진
  - 왼쪽으로 30° ~ 150°: 좌회전
  - 오른쪽으로 30° ~ 150°: 우회전
  - 그 외(거의 되돌아가는 방향): 선택지에서 제외
- 같은 분류에 길이 여러 개면 기준 각도(직진 0°, 좌 −90°, 우 +90°)에 가장 가까운 길 하나만 쓴다.
- 오거리 이상도 같은 규칙으로 좌·직·우 최대 3개로 정리된다.
- 각도 기준값은 설정으로 빼서 실제 동네 데이터로 테스트하며 조정한다.

### 이동 표시

- 결정된 방향의 길을 따라 다음 교차로까지 마커가 실제 도로 모양대로 이동하는 애니메이션을 보여준다.

## 6. 서버 설계

### 원칙

1. **게임 진행은 전부 서버가 판정한다.** 가위바위보 결과, 방향 결정, 위치, 도착, 제한 도달, 횟수, 시간 모두 서버 기준.
2. 클라이언트는 **선택(가위/바위/보)만 보내고**, 결과는 서버가 모두에게 동시에 알린다.
3. 모든 플레이어의 선택이 모이기 전에는 **누가 뭘 냈는지 아무에게도 보내지 않는다.**
4. 플레이 시간은 서버의 게임 시작 시각 기준으로 계산한다.

### 게임 상태 흐름

```
LOBBY (대기)
  → MOVING (다음 교차로까지 이동)
  → RPS (가위바위보, 20초 제한)
      ├─ 한 명 승리 → 방향 결정 → MOVING
      ├─ 두 명 승리 → RPS_REMATCH (두 명끼리, 승자 나올 때까지) → MOVING
      └─ 첫 판 전원 무승부 → 유턴 → MOVING
  → ARRIVED (도착) → 기록 저장 → END
  → LIMIT_REACHED (일반 모드 제한 도달) → [종료 → 기록 저장 → END] / [계속 → MOVING]
  → ABANDONED (포기) → END (하드코어는 기록 없음)
```

### 주요 컬렉션 (초안)

- `rooms`: 방 정보, 초대 코드, 모드, 제한값, 출발지, 목적지, 플레이어 자리(A/B/C) 및 상태(유저 / AI)
- `games`: 진행 중인 게임 상태 (현재 노드, 들어온 방향, 가위바위보 횟수, 이동 거리, 경로, 시작 시각)
- `records`: 종료된 게임 기록
- `roadGraphs`: 지역별 전처리된 도로 그래프 캐시

### 주요 소켓 이벤트 (초안)

| 방향 | 이벤트 | 설명 |
|---|---|---|
| C → S | `room:join` | 방 입장 / 재입장 |
| C → S | `game:start` | 방장이 게임 시작 |
| S → C | `game:moving` | 다음 교차로까지의 경로 |
| S → C | `rps:start` | 가위바위보 시작 (참가자, 가능한 방향, 마감 시각) |
| C → S | `rps:choose` | 가위바위보 선택 |
| S → C | `rps:result` | 모두의 선택과 판정 결과 |
| S → C | `player:replaced` | 플레이어가 AI로 대체됨 |
| S → C | `player:returned` | 유저가 자리로 복귀 |
| S → C | `game:limitReached` | 제한 도달 요약 |
| C → S | `game:limitDecision` | 종료 / 계속 선택 |
| S → C | `game:arrived` | 도착 및 최종 기록 |

### 주요 REST API (초안)

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/auth/guest` | 게스트 계정 생성 |
| GET | `/places/search` | 장소 검색 (카카오 로컬 API 프록시) |
| POST | `/rooms` | 방 생성 |
| GET | `/rooms/:code` | 초대 코드로 방 조회 |
| GET | `/records/me` | 내 기록 목록 |
| GET | `/records/:id` | 기록 상세 (경로 다시 보기) |

## 8. 개발 단계

- **Phase 1 – 길 판정 (솔로, 로컬)**: 출발지 주변 OSM 도로 수집 → 그래프 구성 → 교차로에서 좌·직·우 판정. 도로를 단순한 3D로 그리고, 교차로마다 방향을 직접 골라 이동해 보며 실제 동네로 검증
- **Phase 2 – 싱글 플레이 프로토타입**: 나 + AI 2명으로 가위바위보 → 이동 → 도착까지 전체 루프
- **Phase 3 – 멀티플레이**: Socket.IO, 방 생성·초대 코드, 3인 동시 선택, 20초 제한, AI 대체 및 복귀
- **Phase 4 – 모드와 기록**: 일반 모드(시간/턴 제한, 제한 도달 모달), 하드코어 모드, 기록 저장과 경로 다시 보기
- **Phase 5 – 3D 동네와 캐릭터**: 3D 건물, 로우폴리 캐릭터 3명과 걷기 애니메이션, 카메라 연출, 출발지·목적지 표지
- **Phase 6 – 앱 빌드**: EAS Build로 iOS(TestFlight)·Android 빌드, 백그라운드·재접속 처리, 푸시 알림
- **Phase 7 – 출시 준비**: OSM 자체 전처리 전환, 지도 출처 표기, 개인정보 처리방침, App Store·Play 스토어 동시 출시

## 9. 작업 규칙 (Claude Code 참고)

- 게임 진행 판정 로직은 서버에만 둔다. 클라이언트가 보낸 위치, 횟수, 결과를 신뢰하지 않는다.
- 가위바위보 판정, 방향 분류, 상태 전이는 **순수 함수로 분리하고 단위 테스트**를 작성한다.
- 20초 제한, 도착 반경, 각도 기준 같은 값은 `shared/config`에 상수로 둔다.
- 소켓 이벤트 이름과 페이로드 타입은 `shared/types`에 한 곳에서 정의한다.
- 지도 화면에는 OpenStreetMap 출처를 항상 표시한다.
- 3D 화면 컴포넌트(`client/src/map`)에는 표시만 두고, 판정 로직을 넣지 않는다.
- 한 Phase가 끝날 때마다 동작 확인 후 다음 Phase로 넘어간다.
