# 직좌우 (가제)

**실제 동네 지도 위에서, 교차로마다 가위바위보로 갈 방향을 정하는 3인 온라인 게임.**

세 명이 각자 자기 기기에서 접속해 한 일행을 함께 움직인다. 교차로를 만날 때마다 가위바위보를 하고, 이긴 사람이 맡은 방향으로 간다. 목적지에 도착할 때까지 몇 번의 가위바위보를 했는지, 얼마나 걸렸는지가 기록으로 남는다.

> 목표: 첫 앱 출시 경험 + 포트폴리오. 수익화는 부가 목표.

---

## 1. 게임 규칙

### 플레이어와 방향

| 플레이어 | 담당 방향 |
|---|---|
| A | 좌회전 |
| B | 직진 |
| C | 우회전 |

- 3명은 각자 자기 기기에서 접속한다 (온라인 멀티플레이).
- 세 사람은 지도 위의 **한 일행(마커 하나)**을 함께 움직인다.

### 교차로 가위바위보

1. 일행이 교차로에 도착하면 가위바위보가 시작된다.
2. **그 교차로에 없는 방향을 맡은 플레이어는 이번 판에서 빠진다.**
   - 십자 교차로(좌·직·우): A, B, C
   - 좌·우만 있는 갈림길: A, C
   - 좌·직만 있음: A, B
   - 직·우만 있음: B, C
   - 갈 수 있는 방향이 하나뿐(굽은 길 등): 가위바위보 없이 그 방향으로 진행
   - 막다른 길: 가위바위보 없이 자동 유턴
3. 판정
   - **한 명이 이기면**: 그 사람의 방향으로 이동
   - **두 명이 이기면**: 그 두 명끼리 **한 명이 이길 때까지** 다시 가위바위보 (두 명끼리 비기면 계속 재경기)
   - **첫 판에서 전원 무승부**(모두 같은 것, 또는 셋이 모두 다른 것): **뒤로 돌아간다** (왔던 길로 유턴)
   - 참가자가 두 명인 갈림길에서 첫 판이 비기면: 전원 무승부로 보고 유턴
4. **가위바위보 횟수는 재경기를 포함해 한 판 한 판 모두 센다.**

### 도착 판정

- 목적지는 가장 가까운 도로 지점으로 보정한다.
- 일행이 목적지 반경 안(기본 30m, 조정 가능)에 들어오면 도착으로 처리한다.
- 도착은 일부러 어렵게 둔다. 무작위로 걷기 때문에 300m 거리도 가위바위보 수백~수천 번이 걸릴 수 있고, 그게 이 게임의 재미다. 다만 구조적으로 도착이 불가능한 곳(출구가 선택지에 안 나오는 길 등)은 버그로 보고 고친다.

### 선택 제한 시간과 자리 비움

- 가위바위보마다 **20초** 안에 선택해야 한다.
- 20초 안에 선택하지 않은 플레이어는 **자동 퇴장**되고, 그 자리는 **AI 플레이어**가 이어받는다.
  - 시간이 지난 그 판의 선택도 AI가 대신한다.
  - AI는 가위·바위·보 중 무작위로 낸다.
- 퇴장된 유저가 방으로 돌아오면 **자기 자리를 AI에게서 다시 넘겨받아** 이어서 플레이한다.
  - 진행 중인 판이 있으면 그 판은 AI가 마무리하고, 다음 판부터 유저가 플레이한다.
- 앱이 꺼지거나 네트워크가 끊긴 경우도 같은 방식으로 처리한다.

## 2. 게임 모드

앱을 켜면 로딩 화면(직·좌·우 글자와 세 사람이 하나씩 등장) → 메뉴(BGM, 지금 시각의 하늘과 언덕, 세 사람)가 나온다. 3D 지도는 게임 화면에서만 그린다.
메뉴에는 **혼자서 플레이 / 멀티플레이 / 기록실**이 있고, 혼자·멀티를 누르면 난이도(일반 / 하드코어)를 고른다.

- **혼자서 플레이**: 나 + AI 2명. 대기실 없이 바로 출발한다. 다른 사람은 들어올 수 없다.
- **멀티플레이**: 방을 만들어 초대 코드로 친구를 부르거나, 초대 코드로 참가한다. 빈 자리는 AI.

### 일반 모드 — 가볍게 떠나 보기

방을 만들 때 제한을 하나 고른다.

- **시간 제한**: 10분 / 20분 / 30분
- **횟수 제한**: 가위바위보 100회 / 200회 / 300회 (재경기 포함)

제한을 다 쓰면 그 자리에서 끝난다 (횟수는 마지막 판의 이동까지 마친 다음 교차로에서, 시간은 기다리던 중이어도 바로).
목적지에 얼마나 가까이 갔는지(남은 직선 거리)와 이동 경로·횟수가 함께한 사람 모두의 기록실에 남는다. 제한 전에 도착하면 "도착"으로 남는다.
도중에 포기하면 기록은 남지 않는다.

### 하드코어 모드 — 도착할 때까지

- 제한이 없다. 끝은 도착뿐이고, 중간 저장도 없다. **포기만 할 수 있다.**
- 도착하면 기록실과 **월드레코드**(그날, 한국 시간 기준)에 오른다.

### 방이 없어지는 때

- 멀티에서 한두 명이 나가도 그 자리는 AI가 이어 맡고, 나간 사람은 초대 코드로 다시 들어와 자리를 되찾을 수 있다.
- **접속한 사람이 아무도 없으면 1분 뒤 방이 없어진다** (잠깐 끊긴 것은 봐준다). 모두 나가면(포기하면) 바로 없어진다. 하드코어는 그 판이 그대로 사라진다.

### 기록실

- **내 기록**: 내가 끝까지 함께한 판(일반·하드코어). 누르면 지나온 길 그림(출발·목적지·끝난 곳)과 기록을 본다.
- **월드레코드**: 날짜별로 하드코어로 도착한 판. 정렬 세 가지
  - 총 이동 거리 (짧은 순)
  - 출발지-목적지 직선 거리 (먼 순)
  - 가위바위보 횟수 (적은 순)

| 기록 항목 | 설명 |
|---|---|
| 규칙 | 일반(제한) / 하드코어, 혼자 / 멀티 |
| 결과 | 도착 / 남은 거리 |
| 가위바위보 횟수 | 재경기 포함 |
| 걸린 시간 | 게임 시작부터 끝까지 |
| 총 이동 거리 | 실제 도로 기준 |
| 출발-목적지 직선 거리 | |
| 이동 경로 | 출발지 기준 좌표 (최대 600점으로 솎음) |
| 함께한 사람 | 끝났을 때 방에 있던 사람 (AI 제외) |

기록은 서버의 `server/data/records.db`(SQLite, Node 내장 `node:sqlite`)에 남는다. `RECORDS_DB`로 위치를 바꿀 수 있다.

### 소리

`client/assets/sounds/`의 임시 음원(`node client/scripts/make-sounds.mjs`로 합성)을 쓴다. BGM은 메뉴·기록실에서만, 효과음은 버튼·가위바위보 결과·내가 이긴 판·도착·제한 끝.

게임 준비는 전체 화면 창에서 출발지(검색·지금 위치·지도에서 길게 누르기) → 목적지 순으로 고른다. 미리 정해진 출발지는 없다. 고른 곳마다 서버에 가장 가까운 길을 물어, 300m 안에 길이 없으면 출발할 수 없고, 떨어져 있으면 그 길에서 출발·도착으로 친다고 알려 준다. 서버도 방을 만들 때 출발지·목적지 둘 다 같은 기준으로 다시 확인한다.

**도착**: 길이 도착 원(반경 `ARRIVAL_RADIUS_M`)에 닿는 순간 그 지점에서 멈추고 끝난다(노드 사이여도). 앱은 번쩍 → 위아래 검은 띠 → 카메라가 일행에게 확 다가가 돌고 → 큰 "도착!"과 꽃가루 여러 번, 일행 환호로 연출한다(`ArrivalCelebration`).

**기록 지도**: 기록 상세의 지도는 게임과 같은 타일(길·물·건물)을 SVG로 그린 바탕 위에 지나온 길을 다시보기로 그린다. 끝나면 "다시보기" 버튼. 타일이 너무 많이 걸리는 넓은 판은 건물을 빼고, 더 넓으면 바탕 없이 길만.

**놀이 구역은 대한민국 본토뿐이다.** 타일을 만들 때 대한민국 국경(OSM 관계 307756, 영해 포함) 밖의 길·건물·물은 버리고, 걸을 수 있는 길을 이어진 묶음으로 나눠 가장 큰 묶음(본토)만 출발지·목적지로 쓸 수 있게 한다. 다리 없는 섬, 제주도, 울릉도, 독도는 지도로는 보이지만 고를 수 없다(걸어서 못 가므로). 고속도로·자동차전용도로만 이어진 섬(예: 영종도)도 게임에서 걸을 수 없는 길이라 같이 빠진다. 대한민국 영역 밖(북한·중국·일본)은 타일을 받지 않고, 카메라도 그 밖으로 끌려가지 않으며, 장소 검색 결과에서도 뺀다.

아이콘은 글자 이모지 대신 [Microsoft Fluent Emoji](https://github.com/microsoft/fluentui-emoji) 3D 그림(MIT, `client/assets/emoji/LICENSE`)을 192px로 줄여 쓴다. 이름 → 파일은 `client/src/ui/Icon.tsx`.

가위바위보 결과는 지도 가운데 창으로 보여 준다. 모두 내면 "가위! 바위! 보!"를 한 단어씩 외치고(`RPS_CHANT_MS`) 낸 손을 공개한다. 이기면 꽃종이, 지면 창이 흔들린다. 게임 중 아래 패널은 높이가 고정이라 지도가 흔들리지 않는다. 소리·진동 설정과 게임 나가기는 지도 오른쪽 위 메뉴 버튼에 있다(진동 설정은 소리 설정과 함께 기기에 저장).
진짜 음원으로 바꿀 때는 같은 이름 파일을 덮어쓴다 (확장자를 바꾸면 `client/src/lib/sound.ts`도). 메뉴의 🔊로 끌 수 있다.

### 코인 · 미션 · 옷장

코인으로 옷장에서 캐릭터를 꾸민다 (모자 / 상의 / 하의 / 소품). 입은 옷은 같은 방 사람과 근처 다른 방 사람에게도 보인다.
값(보상·가격·미션)은 모두 `shared/config/economy.ts`에 있다.

코인을 버는 방법:
- **출석**: 하루 한 번. 연속 출석일수에 따라 10·10·15·15·20·20·50 (7일마다 처음부터, 하루 빠지면 1일째부터)
- **판을 끝까지 하기** (포기는 없음): 일반 끝 10 / 일반 도착 30 (일반은 하루 10판까지) / 하드코어 도착 150
- **일일 미션**(매일 0시) · **주간 미션**(월요일 0시): 게임한 시간, 가위바위보 횟수, 끝낸 판 수, 도착, 출석 일수. 다 하면 미션 화면에서 받기

AI에게 맡겨 두고 쌓는 것을 막기 위해, 가위바위보 횟수는 직접 낸 것만, 게임한 시간은 최근 3분 안에 직접 낸 적이 있을 때만 센다.
클리어 보상도 그 판에서 3번 이상 직접 낸 사람만 받는다. 날짜는 한국 시간 기준.

지금은 게스트 id(기기에 저장)에 묶여 있어서 앱을 지우면 코인과 옷도 사라진다. 계정 연결은 나중에.
광고 보상은 배포 단계에서 (Expo Go에서는 광고 모듈을 쓸 수 없다).

### 땅 높이 (산·언덕)

- 고도 데이터는 공개 고도 타일(AWS Terrain Tiles, Terrarium 형식, SRTM 등 기반, 약 30m 간격)을 쓴다. 가입·키가 필요 없다.
- 서버가 지도 타일 한 칸을 처음 요청받을 때 원본을 받아 33×33 높이 격자로 만들고, 둘 다 `server/data/terrain/`에 남겨 다음부터는 다시 받지 않는다. 처음 가는 동네는 그래서 조금 늦게 뜰 수 있다.
- 앱의 월드 높이(y)는 해발 m 그대로다. 땅·도로·건물·물·캐릭터·깃발·카메라가 모두 그 자리 땅 높이를 찾아 올라간다 (`client/src/map/terrain.ts`의 `heightAt`).
- 고도 데이터가 지표면 기준이라 고층 건물이 많은 곳은 땅이 조금 울퉁불퉁할 수 있다.
- 남산서울타워는 지도 데이터에 건물로 없어서 남산 꼭대기에 따로 세운다 (`client/src/map/SeoulTower.tsx`).

### 낮과 밤

- 로딩 화면과 메뉴의 하늘은 지금 한국 시각을 따른다.
- 게임은 늘 아침 9시에서 시작하고, 실제 1분에 게임 속 1시간씩 흐른다 (24분이면 하루). 판을 새로 시작하면 다시 아침.
- 저녁이 되면 하늘·빛이 바뀌고, 건물 창문 일부와 길가 가로등이 켜진다. 실제 조명 대신 밤에만 보이는 빛나는 면이라 가볍다.
- 값은 `client/src/map/daylight.ts` (시각별 하늘색·빛 세기, 시작 시각, 흐르는 빠르기).

### 이모티콘과 근처 플레이어

- 게임 중 지도 오른쪽 😀 버튼으로 이모티콘 8가지를 보낸다. 캐릭터가 그 동작(손 흔들기, 박수, 만세 등)을 하고 머리 위에 잠깐 뜬다. 1.5초에 한 번까지.
- 반경 1.2km 안에서 게임 중인 **다른 방 일행**이 반투명하게 걸어 다닌다 (가까운 순 6팀까지). 그 일행의 이모티콘도 보인다.
- 다른 방에는 지금 위치·옷·걸어간 길만 보낸다. 이름·출발지·목적지·지나온 길·방 코드는 보내지 않는다.

## 3. 방

- 메뉴에서 고른 **모드와 제한**으로, 방장이 **출발지(동네)**와 **목적지**를 정해 방을 만든다.
- 출발지와 목적지는 장소 검색으로 찾거나 지도를 길게 눌러 고른다. 고른 위치에 뜨는 카드에서 [출발] / [도착]을 누른다.
- 목적지가 출발지에서 너무 멀면 경고한다 (무작위 이동이라 거리가 멀면 도착이 매우 어렵다).
- 친구는 초대 코드로 입장한다.
- 입장 순서 또는 방장 지정으로 A / B / C 자리를 배정한다.
- 방장이 시작한다. 빈 자리는 AI가 맡는다.

## 4. 지도와 길 판정

### 데이터 소스

- **도로 그래프**: OpenStreetMap (ODbL 라이선스, 앱 내 출처 표기 필수)
  - Geofabrik의 대한민국 OSM 추출본(.osm.pbf)을 받아 서버에서 지도 타일로 미리 쪼개 보관한다. 외부 API에 의존하지 않고, 어느 동네든 바로 열린다.
  - 타일: 위도·경도 0.01도 격자(약 0.9km × 1.1km). 칸마다 보행 도로, 건물(윤곽·높이), 물(호수·강·하천)을 gzip JSON으로 저장한다.
  - 준비: `npm run osm:download -w server`(원본 받기) → `npm run osm:tiles -w server`(타일 만들기). 원본은 매일 갱신되므로 필요할 때 다시 돌린다. 타일 폴더에 대한민국 영역(`region.json`)과 섬 노드 표시(도로 타일의 `off`)도 함께 만든다.
- **보행 가능 도로만 사용**: 고속도로, 자동차 전용도로 등은 제외한다.
- **장소 검색**: 카카오 로컬 API (한국어 장소명 검색). 서버 `server/.env`에 `KAKAO_REST_API_KEY`를 넣는다 (`server/.env.example` 참고). 키가 없으면 OpenStreetMap Nominatim으로 대신 찾는다 (한국 상호는 약하다).
- **지도 표시**: 지도 SDK 없이, 위 타일의 도로·건물·물 데이터로 3D 동네를 직접 그린다 (아래 "3D 동네 표현").

### 3D 동네 표현

- **렌더링**: Three.js + React Three Fiber (네이티브, expo-gl)
- **도로**: OSM 도로를 폭이 있는 띠(메시)로 바닥에 그린다. 큰길과 골목은 폭과 색으로 구분한다.
- **건물**: OSM 건물 윤곽을 층수(`building:levels`)만큼 올린 로우폴리 블록으로 그린다. 층수 정보가 없으면 기본 높이를 쓴다.
- **물**: 호수·강(멀티폴리곤, 섬은 구멍)은 면으로, 면이 없는 하천은 폭이 있는 띠로 그린다.
- **캐릭터**: 3명(A/B/C)이 상자로 만든 블록 인형으로 실제 도로를 따라 걷는다 (코드로 만든 모델, 부위마다 옷을 갈아입힌다).
- **카메라**: 일행을 따라가는 비스듬한 게임 시점. 조작은 지도 앱과 같다: 한 손가락 끌기 = 지도 이동, 두 손가락 벌리기/오므리기 = 확대/축소(최대 약 3.5km 높이), 비틀기 = 회전, 두 손가락 함께 위아래 = 기울기. 지도를 끌면 따라가기가 풀리고 ◎ 버튼으로 일행(설정 화면에서는 출발지)에게 돌아온다. 기기 가로·세로 회전을 모두 지원한다.
- **장소 표시**: 지도 앱 수준의 상호명은 표시하지 않는다. 출발지·목적지만 표지로 보여준다. 목적지에는 하늘로 솟은 빛기둥을 세워 멀리서도 방향을 알 수 있게 한다.
- **성능**: 도로 그래프는 서버가 갖고(일행 주변 3km, 1.5km 안에 안 읽은 칸이 생기면 그 자리에서 넓힌다), 앱은 화면 중심 주변 1.5km(멀리 축소하면 최대 3km) 타일만 받아 그리며 그보다 1km 더 먼 타일은 내린다. 멀리 볼 때는 덜 그린다: 건물은 화면 중심 1.3km 안 타일만, 골목·산책로는 카메라 1.5km 이내, 교차로 점은 600m 이내일 때만. 받은 타일은 40ms 간격으로 하나씩 화면에 넣어 메시 만드는 일이 한 프레임에 몰리지 않게 한다. 호수·강은 물마다 한 번만 삼각분할한다. 타일마다 도로·건물을 하나의 메시로 합친다.

### 그래프 구성

- 도로를 **노드(지점)와 엣지(길)**로 변환한다.
- 연결된 길이 3개 이상인 노드 = **교차로**
- 연결된 길이 2개인 노드 = 그냥 지나가는 지점 (가위바위보 없음)
- 연결된 길이 1개인 노드 = **막다른 길** (자동 유턴)

### 좌·직·우 판정

- 들어온 길의 진행 방향과 나갈 수 있는 각 길의 방향(bearing) 차이로 분류한다.
  - 차이 −30° ~ +30°: 직진
  - 왼쪽으로 30° ~ 150°: 좌회전
  - 오른쪽으로 30° ~ 150°: 우회전
  - 그 외(거의 되돌아가는 방향): 선택지에서 제외
- 같은 분류에 길이 여러 개면 바로 옆 분류(좌↔직, 직↔우)가 비어 있을 때 그쪽으로 옮겨 둘 다 갈 수 있게 한다 (예: 49°·73° 두 갈래 → 직진·우회전). 왼쪽 길이 오른쪽 길보다 오른쪽 분류가 되지는 않는다.
  - 그래도 남는 길은 기준 각도(직진 0°, 좌 −90°, 우 +90°)에 가장 가까운 길을 쓴다.
  - 길을 버리면 작은 원형 산책로처럼 출구에 영영 못 가는 곳이 생기기 때문이다.
- 외길·막다른 길로 자동 이동하다 같은 곳을 다시 지나게 되면, 판정에서 빠졌던 다른 길로 빠져나간다 (고리 길에서 끝없이 도는 것 방지).
- 오거리 이상도 같은 규칙으로 좌·직·우 최대 3개로 정리된다.
- 각도 기준값은 설정으로 빼서 실제 동네 데이터로 테스트하며 조정한다.

### 이동 표시

- 결정된 방향의 길을 따라 다음 교차로까지 마커가 실제 도로 모양대로 이동하는 애니메이션을 보여준다.
- 서버는 한 요청에서 일어난 일(가위바위보 결과, 이동)을 순서대로 이벤트 목록으로 보내고, 앱은 그것을 차례로 연출한다. 다음 가위바위보 마감(20초)은 연출 시간(이동 속도 `MOVE_SPEED_MPS`, 결과 표시 `RPS_RESULT_SHOW_MS`)만큼 늦춰 잡는다.
- 출발 방향은 무작위로 정한다.

## 6. 서버 설계

### 원칙

1. **게임 진행은 전부 서버가 판정한다.** 가위바위보 결과, 방향 결정, 위치, 도착, 제한 도달, 횟수, 시간 모두 서버 기준.
2. 클라이언트는 **선택(가위/바위/보)만 보내고**, 결과는 서버가 모두에게 동시에 알린다.
3. 모든 플레이어의 선택이 모이기 전에는 **누가 뭘 냈는지 아무에게도 보내지 않는다.**
4. 플레이 시간은 서버의 게임 시작 시각 기준으로 계산한다.

### 게임 상태 흐름

```
LOBBY (대기)
  → MOVING (다음 교차로까지 이동)
  → RPS (가위바위보, 20초 제한)
      ├─ 한 명 승리 → 방향 결정 → MOVING
      ├─ 두 명 승리 → RPS_REMATCH (두 명끼리, 승자 나올 때까지) → MOVING
      └─ 첫 판 전원 무승부 → 유턴 → MOVING
  → ARRIVED (도착) → 기록 저장 → END
  → LIMIT_REACHED (일반 모드 제한 도달) → [종료 → 기록 저장 → END] / [계속 → MOVING]
  → ABANDONED (포기) → END (하드코어는 기록 없음)
```

### 주요 컬렉션 (초안)

- `rooms`: 방 정보, 초대 코드, 모드, 제한값, 출발지, 목적지, 플레이어 자리(A/B/C) 및 상태(유저 / AI)
- `games`: 진행 중인 게임 상태 (현재 노드, 들어온 방향, 가위바위보 횟수, 이동 거리, 경로, 시작 시각)
- `records`: 종료된 게임 기록
- `roadGraphs`: 지역별 전처리된 도로 그래프 캐시

### 소켓 이벤트

타입은 `shared/types/room.ts`에 한 곳에서 정의한다. 요청(C → S)은 모두 ack로 `{ ok: true, ... } | { ok: false, error }`를 돌려받는다.

| 방향 | 이벤트 | 설명 |
|---|---|---|
| C → S | `room:create` | 닉네임·출발지·목적지·규칙(`rules`)·혼자 여부(`solo`)로 방 만들기 → 초대 코드. 혼자면 앱이 바로 `game:start` |
| C → S | `room:join` | 초대 코드로 입장. 재접속도 같은 이벤트 (게임 중이면 지나온 길과 지금 상태를 받는다) |
| C → S | `room:seat` | 대기실에서 빈 자리로 옮기기 |
| C → S | `room:leave` | 방 나가기·포기 (게임 중이면 그 자리는 AI가 계속 맡는다. 마지막 사람이면 방이 없어진다) |
| C → S | `game:start` | 방장이 시작. 빈 자리는 AI |
| C → S | `game:reset` | 방장이 끝난 게임에서 대기실로 |
| C → S | `rps:choose` | 가위바위보 선택 |
| C → S | `seat:return` | AI가 대신하던 내 자리를 다음 판부터 다시 맡기 |
| C → S | `emote:send` | 이모티콘 보내기 (게임 중·끝난 뒤) |
| S → C | `room:state` | 방 정보 (참가자, 자리, 접속 여부, 방장, 상태, 규칙, 끝난 판의 기록 id) |
| S → C | `game:intro` | 게임 시작: 목적지, 출발 지점 |
| S → C | `game:update` | 일어난 일(가위바위보 결과, 이동) 목록 + 지금 상태 (누가 냈는지, 자리마다 사람/AI, 마감까지 남은 시간) |
| S → C | `emote` | 같은 방 사람의 이모티콘 (자리, 이모티콘) |
| S → C | `ghost:list` | 근처 다른 방 일행 목록 (2초마다: 게임마다 새 id, 지금 위치, 자리별 옷) |
| S → C | `ghost:move` | 다른 방 일행이 걸어간 길 |
| S → C | `ghost:emote` | 다른 방 일행의 이모티콘 |

- 누가 무엇을 냈는지는 그 판의 사람이 모두 내기 전까지 아무에게도 보내지 않는다 (`submitted`에는 낸 자리만 있다).
- 20초 마감은 서버 타이머가 지킨다. 마감이 지나면 안 낸 자리는 AI로 바뀌고 그 판을 AI가 낸다.
- 사람이 한 명도 없으면(모두 시간 초과) 게임은 멈추고, 누군가 돌아오면 이어진다.
- 앱은 초대 코드와 게스트 신원(기기에 저장한 id·닉네임)을 기억해, 끊기거나 앱을 다시 켜면 하던 방으로 돌아간다.

### 휴대폰 한 대로 멀티플레이 시험하기

`npm run bot -w server -- <초대코드>`: PC에서 가짜 플레이어 2명이 들어와 무작위로 낸다.
- `--count 1`: 1명만
- `--skip 0.3`: 판마다 30% 확률로 일부러 안 내서 시간 초과·AI 대체·돌아오기를 시험
- `--drop 0.1`: 접속을 끊었다 다시 들어오기를 시험
- `--create`: 봇끼리만 방을 만들어 돌린다

## 8. 개발 단계

- **Phase 1 – 길 판정 (솔로, 로컬)**: 출발지 주변 OSM 도로 수집 → 그래프 구성 → 교차로에서 좌·직·우 판정. 도로와 건물을 3D로 그리고, 교차로마다 방향을 직접 골라 이동해 보며 실제 동네로 검증
- **Phase 2 – 싱글 플레이 프로토타입**: 나 + AI 2명으로 가위바위보 → 이동 → 도착까지 전체 루프. 목적지는 지도를 길게 눌러(또는 좌표로) 고른다
- **Phase 3 – 멀티플레이**: Socket.IO, 방 생성·초대 코드, 3인 동시 선택, 20초 제한, AI 대체 및 복귀
- **Phase 4 – 모드와 기록**: 일반 모드(시간/턴 제한, 제한 도달 모달), 하드코어 모드, 기록 저장과 경로 다시 보기
- **Phase 5 – 3D 동네와 캐릭터**: 건물 외형 다듬기, 로우폴리 캐릭터 3명과 걷기 애니메이션, 카메라 연출, 출발지·목적지 표지
- **Phase 6 – 앱 빌드**: EAS Build로 iOS(TestFlight)·Android 빌드, 백그라운드·재접속 처리, 푸시 알림
- **Phase 7 – 출시 준비**: 지도 타일 정기 갱신, 지도 출처 표기, 개인정보 처리방침, App Store·Play 스토어 동시 출시

## 9. 작업 규칙 (Claude Code 참고)

- 게임 진행 판정 로직은 서버에만 둔다. 클라이언트가 보낸 위치, 횟수, 결과를 신뢰하지 않는다.
- 가위바위보 판정, 방향 분류, 상태 전이는 **순수 함수로 분리하고 단위 테스트**를 작성한다.
- 20초 제한, 도착 반경, 각도 기준 같은 값은 `shared/config`에 상수로 둔다.
- 소켓 이벤트 이름과 페이로드 타입은 `shared/types`에 한 곳에서 정의한다.
- 지도 화면에는 OpenStreetMap 출처를 항상 표시한다.
- 3D 화면 컴포넌트(`client/src/map`)에는 표시만 두고, 판정 로직을 넣지 않는다.
- 한 Phase가 끝날 때마다 동작 확인 후 다음 Phase로 넘어간다.
